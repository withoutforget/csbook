# Математическая логика: пропозициональная и предикатная

## Введение

Математическая логика — это раздел математики, изучающий формальные системы, в которых можно точно выражать и доказывать математические утверждения. Она является основой теории типов, формальной верификации программ, языков запросов и систем вывода типов в компиляторах.

Для разработчика математическая логика — это не абстрактная дисциплина, а инструмент. Система типов Haskell основана на логике Хиндли–Милнера. SQL-оптимизатор переписывает запросы, пользуясь логическими тождествами. Верификаторы Coq и Isabelle/HOL позволяют доказывать корректность программ математически строго. Понимание логики помогает писать более корректный и надёжный код.

## 1. Пропозициональная логика

Пропозициональная (высказывательная) логика изучает высказывания — утверждения, которые могут быть истинными (T, 1) или ложными (F, 0) — и логические связки между ними.

### Атомарные высказывания и связки

Атомарное высказывание — это простое утверждение, не разложимое на части. Примеры: «2 чётное», «Солнце светит». Из атомарных высказываний строятся составные с помощью логических связок:

| Связка | Обозначение | Читается | Истинна когда |
|---|---|---|---|
| Отрицание | $\lnot p$ | «не p» | p ложно |
| Конъюнкция | $p \land q$ | «p и q» | оба истинны |
| Дизъюнкция | $p \lor q$ | «p или q» | хотя бы одно истинно |
| Импликация | $p \to q$ | «если p, то q» | не бывает p=T и q=F |
| Эквивалентность | $p \leftrightarrow q$ | «p тогда и только тогда, когда q» | оба одновременно T или F |
| Исключающее или | $p \oplus q$ | «p XOR q» | ровно одно истинно |

### Таблицы истинности

```
p  | q  | p∧q | p∨q | p→q | p↔q
---|----|-----|-----|-----|----
T  | T  |  T  |  T  |  T  |  T
T  | F  |  F  |  T  |  F  |  F
F  | T  |  F  |  T  |  T  |  F
F  | F  |  F  |  F  |  T  |  T
```

Особое внимание — импликации. «Если p, то q» ($p \to q$) ложна только в одном случае: когда $p$ истинна, а $q$ ложна. Это контринтуитивно: «Если дождь, то мокро» — истинно. «Если нет дождя, то мокро» — тоже истинно (мокро может быть от тумана). «Если дождь, то не мокро» — ложно.

В программировании импликация реализуется как `!p || q`:

```python
def implies(p, q):
    return (not p) or q

# Проверка: "если x > 0, то x * x > 0"
for x in [-2, -1, 0, 1, 2]:
    p = x > 0
    q = x * x > 0
    print(f"x={x}: p={p}, q={q}, p→q={implies(p, q)}")
```

### Тавтологии и противоречия

**Тавтология** — формула, истинная при любых значениях переменных. Пример: $p \lor \lnot p$ (закон исключённого третьего).

**Противоречие** — формула, ложная при любых значениях. Пример: $p \land \lnot p$.

**Выполнимая формула** — истинная хотя бы при одном наборе значений.

Задача проверки выполнимости пропозициональной формулы — это задача SAT, и она является NP-полной (теорема Кука–Левина, 1971). Это фундаментальный факт теоретической информатики.

### Нормальные формы

Любую пропозициональную формулу можно преобразовать к нормальной форме:

**КНФ (конъюнктивная нормальная форма)** — конъюнкция клоз, каждая клоза — дизъюнкция литералов:

$$( p \lor q \lor \lnot r) \land (\lnot p \lor s) \land (r \lor \lnot s)$$

**ДНФ (дизъюнктивная нормальная форма)** — дизъюнкция конъюнктов:

$$(p \land q) \lor (\lnot p \land r) \lor (q \land \lnot r)$$

Алгоритмы SAT-решателей работают именно с КНФ. Задачи планирования, проверки моделей, анализа схем — всё это сводится к SAT.

## 2. Логические эквивалентности

Две формулы логически эквивалентны, если они имеют одинаковые таблицы истинности. Важнейшие эквивалентности:

### Законы де Моргана

$$\lnot(p \land q) \equiv \lnot p \lor \lnot q$$
$$\lnot(p \lor q) \equiv \lnot p \land \lnot q$$

**Практическое применение**: оптимизация SQL-запросов.

```sql
-- Эти два запроса эквивалентны:
SELECT * FROM users WHERE NOT (age < 18 AND country = 'RU');
SELECT * FROM users WHERE age >= 18 OR country != 'RU';
```

Оптимизатор базы данных использует именно такие логические преобразования для поиска более эффективного плана выполнения запроса.

### Контрапозиция

$$(p \to q) \equiv (\lnot q \to \lnot p)$$

«Если идёт дождь, то улица мокрая» логически эквивалентно «Если улица сухая, то дождя нет». Это ключевой приём в доказательствах от противного.

### Экспортация

$$(p \land q) \to r \;\equiv\; p \to (q \to r)$$

Это соответствует каррированию функций в функциональном программировании: функция двух аргументов эквивалентна функции одного аргумента, возвращающей функцию одного аргумента.

```python
# Функция с двумя аргументами
def add(x, y):
    return x + y

# Каррированная версия: (x ∧ y) → result ≡ x → (y → result)
def curried_add(x):
    return lambda y: x + y

add(3, 4)          # 7
curried_add(3)(4)  # 7
```

## 3. Методы вывода

Формальный вывод — это цепочка шагов, каждый из которых является либо предположением, либо результатом применения правила вывода к ранее полученным шагам.

### Modus Ponens

Если $p$, и из $p$ следует $q$, то $q$:

$$\frac{p \quad p \to q}{q}$$

Это основное правило вывода. Все интерпретаторы и компиляторы по сути применяют modus ponens в разных формах.

### Modus Tollens

$$\frac{\lnot q \quad p \to q}{\lnot p}$$

«Если система не выдаёт ошибку, то код корректен» → «Код некорректен» → «Система должна выдавать ошибку».

### Правило резолюции

$$\frac{(p \lor q) \quad (\lnot q \lor r)}{(p \lor r)}$$

Метод резолюции — основа автоматического доказательства теорем и Prolog-интерпретаторов. Prolog программы выполняются путём применения резолюции к логическим предложениям.

## 4. Предикатная (первопорядковая) логика

Пропозициональная логика работает с отдельными высказываниями. Предикатная логика позволяет выражать свойства объектов и отношения между ними, что делает её значительно более выразительной.

### Предикаты

Предикат — это функция, принимающая объекты и возвращающая истинностное значение.

- $P(x)$ = «x чётное»
- $Q(x, y)$ = «x больше y»
- $R(x, y, z)$ = «$x + y = z$»

В программировании предикаты — это функции, возвращающие bool:

```python
def is_even(x): return x % 2 == 0
def greater_than(x, y): return x > y
def adds_to(x, y, z): return x + y == z
```

### Кванторы

Кванторы позволяют выражать свойства, применимые ко всем или некоторым объектам:

- **Квантор всеобщности** $\forall$: «для всех $x$ выполняется $P(x)$»
- **Квантор существования** $\exists$: «существует $x$, для которого выполняется $P(x)$»

$$\forall x\,(P(x) \to Q(x)) \quad\text{— «Все объекты со свойством $P$ обладают и $Q$»}$$
$$\exists x\, P(x) \quad\text{— «Существует объект со свойством $P$»}$$
$$\exists!\, x\, P(x) \quad\text{— «Существует единственный объект со свойством $P$»}$$

### Эквивалентности с кванторами

$$\lnot\,\forall x\, P(x) \equiv \exists x\, \lnot P(x) \quad\text{— «Не все» $\equiv$ «Существует хотя бы один, не обладающий»}$$
$$\lnot\,\exists x\, P(x) \equiv \forall x\, \lnot P(x) \quad\text{— «Ни одного» $\equiv$ «Все не обладают»}$$

**Пример в SQL**:
```sql
-- ∀x (User(x) → HasEmail(x))
-- «Все пользователи имеют email»
-- Проверяем через отрицание: ∃x (User(x) ∧ ¬HasEmail(x))
SELECT COUNT(*) FROM users WHERE email IS NULL;

-- ∃x (Product(x) ∧ Price(x) < 100)
-- «Существует товар дешевле 100»
SELECT 1 FROM products WHERE price < 100 LIMIT 1;
```

## 5. Логика и типы

Соответствие Карри–Ховарда (Curry–Howard correspondence) — одно из глубочайших открытий теоретической информатики: типы в программировании соответствуют логическим формулам, а программы — доказательствам.

| Логика | Типы |
|---|---|
| Пропозиция $A$ | Тип $A$ |
| Доказательство $A$ | Программа типа $A$ |
| $A \land B$ | Пара $(A, B)$ |
| $A \lor B$ | Сумма (Either A B) |
| $A \to B$ | Функция $A \to B$ |
| $\bot$ (ложь) | Тип без значений (Never, Void) |
| $\forall x\, P(x)$ | Обобщённая (генерик) функция |
| $\exists x\, P(x)$ | Зависимая пара |

Именно это соответствие лежит в основе систем типов таких языков как Haskell, Idris, Coq, Agda. В Coq тип `List.length` — это одновременно доказательство свойства длины списка.

```haskell
-- В Haskell тип (a, b) соответствует логической конъюнкции A ∧ B
-- Пара содержит ОБА значения
conjunct :: (a, b) -> a
conjunct (x, _) = x  -- "извлечение" как modus ponens из A ∧ B → A

-- Тип Either a b соответствует дизъюнкции A ∨ B
-- Содержит ОДНО из значений
disjunct :: Either a b -> String
disjunct (Left _)  = "Left component"
disjunct (Right _) = "Right component"
```

### Зависимые типы

В языках с зависимыми типами (Idris, Coq) тип может зависеть от значения. Это позволяет выражать свойства программ на уровне типов:

```idris
-- Тип вектора длины n
data Vect : Nat -> Type -> Type where
  Nil : Vect 0 a
  (::) : a -> Vect n a -> Vect (S n) a

-- Функция append с доказательством длины результата в типе
append : Vect m a -> Vect n a -> Vect (m + n) a
```

Если программа компилируется — её длина гарантированно правильная. Это и есть «доказательства как программы».

## 6. Нормальные формы и алгоритмы SAT

### Алгоритм Цейтина

Преобразование произвольной формулы в КНФ может привести к экспоненциальному увеличению размера. Алгоритм Цейтина вводит вспомогательные переменные для каждой подформулы, что даёт КНФ полиномиального размера. Для подформулы $g = f_1 \land f_2$ вводим переменную $y$:

$$y \leftrightarrow (f_1 \land f_2) \;\equiv\; (\lnot y \lor f_1) \land (\lnot y \lor f_2) \land (y \lor \lnot f_1 \lor \lnot f_2)$$

### DPLL и CDCL

Алгоритм DPLL (Davis–Putnam–Logemann–Loveland) — классический SAT-алгоритм на основе поиска с возвратами. Современные SAT-решатели (MiniSat, Glucose, Kissat) используют CDCL (Conflict-Driven Clause Learning) — расширение DPLL с «обучением» на конфликтах.

SAT-решатели применяются в:
- Формальной верификации (проверка эквивалентности схем)
- Анализе программ (поиск ошибок)
- Криптографическом анализе
- Планировании и оптимизации

## 7. Логика Хоара и верификация программ

Логика Хоара (Hoare logic, 1969) — формальная система для доказательства корректности программ. Основной элемент — тройка Хоара $\{P\}\; S\; \{Q\}$.

Читается: «Если перед выполнением программы $S$ выполняется предусловие $P$, то после выполнения $S$ будет выполняться постусловие $Q$».

### Правила вывода

**Присваивание**:

$$\{Q[E/x]\}\; x := E\; \{Q\}$$

Предусловие — это постусловие, в котором $x$ заменена на $E$.

**Условный оператор**:

$$\frac{\{P \land B\}\; S_1\; \{Q\} \quad \{P \land \lnot B\}\; S_2\; \{Q\}}{\{P\}\;\text{if } B \text{ then } S_1 \text{ else } S_2\;\{Q\}}$$

**Цикл (инвариант)**:

$$\frac{\{P \land B\}\; S\; \{P\}}{\{P\}\;\text{while } B \text{ do } S\;\{P \land \lnot B\}}$$

Инвариант цикла — свойство, сохраняющееся на каждой итерации. Его нахождение — ключевой шаг в доказательстве корректности алгоритмов.

```python
# Пример: бинарный поиск
# Инвариант: если target в arr, то он находится в arr[lo..hi]
def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    # Инвариант: arr[lo..hi] содержит target (если он есть)
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1  # Инвариант сохраняется: target > arr[mid]
        else:
            hi = mid - 1  # Инвариант сохраняется: target < arr[mid]
    return -1
```

## 8. Темпоральная логика и верификация систем

Обычная логика описывает статические свойства. Темпоральная логика позволяет описывать свойства, изменяющиеся во времени, что критически важно для верификации параллельных и реактивных систем.

### LTL (Linear Temporal Logic)

Дополнительные операторы:
- **$\mathbf{X}\,\varphi$**: «в следующий момент $\varphi$»
- **$\mathbf{G}\,\varphi$**: «всегда $\varphi$» (globally)
- **$\mathbf{F}\,\varphi$**: «когда-нибудь $\varphi$» (finally)
- **$\varphi\,\mathbf{U}\,\psi$**: «$\varphi$ Until $\psi$» ($\varphi$ верно до тех пор, пока не стало верно $\psi$)

Примеры свойств систем:

$$\mathbf{G}\,(\text{request} \to \mathbf{F}\,\text{response}) \quad\text{— «Каждый запрос рано или поздно получит ответ»}$$

$$\mathbf{G}\,(\lnot(\text{critical}_1 \land \text{critical}_2)) \quad\text{— «Два процесса не в критической секции одновременно»}$$

$$\mathbf{G}\,(\text{lock} \to \mathbf{X}\,(\text{lock}\;\mathbf{U}\;\text{unlock})) \quad\text{— «После захвата блокировка удержана до освобождения»}$$

Инструменты проверки моделей (model checking): SPIN, NuSMV, TLA+ автоматически верифицируют системы на соответствие LTL/CTL формулам. Amazon использует TLA+ для верификации протоколов DynamoDB и S3.

## 9. Логика в базах данных

SQL основан на реляционном исчислении, которое является вариантом предикатной логики первого порядка.

**Реляционное исчисление кортежей**: $\{t \mid P(t)\}$ — множество кортежей $t$, удовлетворяющих предикату $P$.

SQL-запрос `SELECT * FROM employees WHERE salary > 50000` формально:

$$\{e \mid \text{Employee}(e) \land e.\text{salary} > 50000\}$$

JOIN двух таблиц:

$$\{(e, d) \mid \text{Employee}(e) \land \text{Department}(d) \land e.\text{dept\_id} = d.\text{id}\}$$

Это соответствует SQL:
```sql
SELECT * FROM employees e JOIN departments d ON e.dept_id = d.id;
```

## 10. Практические следствия для разработчика

### Краткий конспект

1. **Законы де Моргана** — упрощают условия в if-else, оптимизируют SQL
2. **Импликация** — понимание того, что доказывает тест: тест проходит $\neq$ код корректен
3. **Кванторы** — точная формулировка требований: «для всех» vs «существует»
4. **Соответствие Карри–Ховарда** — типы как спецификация, компилятор как верификатор
5. **Инварианты цикла** — доказательство корректности алгоритмов

### Пример: верификация функции нахождения минимума

```python
def find_min(arr):
    """
    Предусловие:  len(arr) > 0
    Постусловие:  result == min(arr)
    Инвариант:    result == min(arr[:i])
    """
    result = arr[0]  # Инвариант: result == min(arr[:1])
    for i in range(1, len(arr)):
        # Инвариант: result == min(arr[:i])
        if arr[i] < result:
            result = arr[i]
        # Инвариант сохраняется: result == min(arr[:i+1])
    # После цикла i == len(arr), инвариант: result == min(arr)
    return result
```

## Заключение

Математическая логика — это язык точности. Она позволяет:
- Формально описывать требования к системам
- Доказывать корректность алгоритмов и программ
- Понимать основы систем типов и компиляторов
- Оптимизировать логические выражения в коде и запросах

Это не просто теория — это инструмент, который становится всё более востребованным с ростом сложности систем. Формальная верификация критически важных систем (авиация, медицина, финансы) невозможна без математической логики. Понимание её основ делает разработчика более точным в мышлении и более строгим в написании кода.
