# Криптографические хеш-функции: SHA-2, SHA-3, BLAKE3

## Введение

Криптографическая хеш-функция — это математическое преобразование, принимающее входные данные произвольной длины и возвращающее выход фиксированной длины (хеш, дайджест, отпечаток). Такое преобразование является необратимым и устойчивым к коллизиям. Хеш-функции применяются повсеместно: при проверке целостности файлов, в цифровых подписях, при хранении паролей, в блокчейн системах и в протоколах аутентификации.

Хеш-функции часто называют «цифровыми отпечатками пальцев» данных: даже незначительное изменение входных данных (перевернуть один бит) кардинально меняет хеш-значение. При этом два разных файла теоретически могут иметь одинаковый хеш — это называется коллизией. Безопасность хеш-функции во многом определяется тем, насколько сложно такую коллизию найти.

В этой статье мы рассмотрим три поколения криптографических хеш-функций: семейство SHA-2 (промышленный стандарт), SHA-3/Keccak (принципиально новая конструкция) и BLAKE3 (современный быстрый алгоритм). Также разберём, почему популярные алгоритмы MD5 и SHA-1 больше не безопасны.

## 1. Свойства криптографических хеш-функций

Для того чтобы хеш-функция `H: {0,1}* → {0,1}ⁿ` считалась криптографически безопасной, она должна обладать тремя ключевыми свойствами:

### Pre-image resistance (устойчивость к нахождению прообраза)

Зная хеш `h = H(m)`, вычислительно нереализуемо найти `m` такое, что `H(m) = h`.

Это свойство обеспечивает необратимость: нельзя «декодировать» хеш обратно в исходные данные.

**Нарушение:** Если найдём быстрый алгоритм инвертирования, то хранение хешей паролей становится бессмысленным.

### Second pre-image resistance (устойчивость к нахождению второго прообраза)

Зная `m₁` и `h = H(m₁)`, вычислительно нереализуемо найти `m₂ ≠ m₁` такое, что `H(m₂) = H(m₁)`.

**Нарушение:** Атакующий может подменить документ, сохранив его хеш — цифровая подпись перестаёт обеспечивать целостность.

### Collision resistance (устойчивость к коллизиям)

Вычислительно нереализуемо найти любую пару `m₁ ≠ m₂` такую, что `H(m₁) = H(m₂)`.

Это самое сильное требование — здесь атакующий сам выбирает обе стороны. Коллизии существуют всегда (множество входов бесконечно, множество выходов конечно), но их нахождение должно быть нереализуемым.

### Birthday Paradox и длина хеша

Атака «дней рождения» (birthday attack) — вероятностный метод поиска коллизий. Для n-битного хеша она требует примерно `2^(n/2)` вычислений хеша.

Это аналогия парадокса дней рождения: в комнате из 23 человек вероятность совпадения дней рождения превышает 50%, хотя возможных дней 365.

| Длина хеша | Атака перебором (pre-image) | Birthday attack (коллизии) |
|-----------|---------------------------|---------------------------|
| 128 бит   | 2¹²⁸ ≈ 3.4×10³⁸          | 2⁶⁴ ≈ 1.8×10¹⁹           |
| 160 бит   | 2¹⁶⁰                     | 2⁸⁰ ≈ 1.2×10²⁴           |
| 256 бит   | 2²⁵⁶                     | 2¹²⁸ ≈ 3.4×10³⁸          |
| 512 бит   | 2⁵¹²                     | 2²⁵⁶                     |

Отсюда следует: SHA-256 устойчив к birthday attack на уровне 128 бит безопасности.

## 2. SHA-1 — история и взлом

SHA-1 (Secure Hash Algorithm 1) разработан NSA и опубликован NIST в 1995 году. Размер хеша — 160 бит.

На протяжении многих лет SHA-1 был широко распространён в TLS, Git, GPG, SSH и других протоколах. Однако с годами криптографы находили всё более эффективные атаки:

- **2004:** Ван Сяоюнь (Xiaoyun Wang) нашла метод ускорения поиска коллизий до 2⁶⁹ вместо теоретических 2⁸⁰
- **2005:** Атака усилена до 2⁶³ операций
- **2015:** Сложность оценивалась в $75,000–120,000 за нахождение коллизии через облачные вычисления
- **2017:** Команда Google и CWI Amsterdam создала первую практическую коллизию — проект **SHAttered**

### SHAttered (2017)

Исследователи создали два PDF файла с одинаковым SHA-1 хешем:
```
SHA1("shattered-1.pdf") = 38762cf7f55934b34d179ae6a4c80cadccbb7f0a
SHA1("shattered-2.pdf") = 38762cf7f55934b34d179ae6a4c80cadccbb7f0a
```

Это потребовало около **9.2 квинтиллионов** (9.2×10¹⁸) вычислений SHA-1 — примерно 6500 лет на одном CPU или 110 лет на GPU.

SHA-1 **официально признан небезопасным** для криптографических применений. Git, до недавнего времени использовавший SHA-1 для хеширования объектов, перешёл на SHA-256 в новых репозиториях.

## 3. SHA-2 — Merkle-Damgård конструкция

Семейство SHA-2 разработано NSA и стандартизировано NIST в 2001 году. Включает варианты с разными размерами выхода:

| Вариант   | Размер хеша | Размер блока | Применение                          |
|-----------|------------|--------------|-------------------------------------|
| SHA-224   | 224 бит    | 512 бит      | SHA-256 с обрезанием                |
| SHA-256   | 256 бит    | 512 бит      | Стандарт для большинства применений |
| SHA-384   | 384 бит    | 1024 бит     | TLS, сертификаты                    |
| SHA-512   | 512 бит    | 1024 бит     | Высокая безопасность                |
| SHA-512/256 | 256 бит  | 1024 бит     | Быстрее SHA-256 на 64-битных CPU    |

### Конструкция Меркла-Дамгора

SHA-2 построен на конструкции **Меркла-Дамгора** (Merkle-Damgård):

1. Входное сообщение **дополняется** (padding) до кратной блоку длины: добавляется бит 1, затем нули, затем 64-битная длина исходного сообщения
2. Сообщение делится на блоки фиксированного размера (512 бит для SHA-256)
3. Инициализируются **восемь 32-битных переменных состояния** `h₀...h₇` константными значениями (дробные части квадратных корней простых чисел — «ничего в рукаве»)
4. Итерационная **функция сжатия**: каждый блок сообщения смешивается с текущим состоянием через серию раундов (64 раунда для SHA-256)
5. После обработки всех блоков конкатенация h₀...h₇ даёт финальный хеш

```
Инициализация:
H = (h₀, h₁, ..., h₇)  ← константы

Для каждого блока M_i:
H = compress(H, M_i)    ← необратимое смешивание

Результат: H₀ || H₁ || ... || H₇
```

### Раунды SHA-256

Функция сжатия SHA-256 выполняет 64 раунда, используя 64 константы `K[0..63]` (дробные части кубических корней первых 64 простых чисел) и **расписание сообщения** (message schedule) — расширение 16 слов блока до 64 слов.

```python
import struct

# Константы SHA-256 (первые 8 из 64)
K = [
    0x428a2f98, 0x71374491, 0xb5c0fbcf, 0xe9b5dba5,
    # ... всего 64 константы
]

def ch(x, y, z):
    return (x & y) ^ (~x & z)

def maj(x, y, z):
    return (x & y) ^ (x & z) ^ (y & z)

def sigma0(x):
    return rotr(x, 2) ^ rotr(x, 13) ^ rotr(x, 22)

def sigma1(x):
    return rotr(x, 6) ^ rotr(x, 11) ^ rotr(x, 25)

# В каждом раунде обновляются 8 рабочих переменных a..h
```

### SHA-256 на Python

```python
import hashlib

data = b"Hello, World!"

# SHA-256
h256 = hashlib.sha256(data).hexdigest()
print(f"SHA-256: {h256}")
# Вывод: dffd6021bb2bd5b0af676290809ec3a53191dd81c7f70a4b28688a362182986d

# SHA-512
h512 = hashlib.sha512(data).hexdigest()
print(f"SHA-512: {h512[:64]}...")  # Первые 32 байта из 64

# Для потоковой обработки больших файлов
def hash_file(path: str, algorithm: str = "sha256") -> str:
    h = hashlib.new(algorithm)
    with open(path, 'rb') as f:
        while chunk := f.read(65536):  # Читаем по 64KB
            h.update(chunk)
    return h.hexdigest()

# Лавинный эффект (avalanche effect): один бит → другой хеш
h1 = hashlib.sha256(b"hello").hexdigest()
h2 = hashlib.sha256(b"hello!").hexdigest()
print(f"\nLavine effect demo:")
print(f"SHA256('hello'):  {h1}")
print(f"SHA256('hello!'): {h2}")

# Подсчёт различающихся бит
diff_bits = bin(int(h1, 16) ^ int(h2, 16)).count('1')
print(f"Различающихся бит: {diff_bits} из 256 ({diff_bits/256*100:.1f}%)")
# Ожидается ~50% = ~128 бит
```

### Уязвимость Length Extension Attack

Конструкция Меркла-Дамгора уязвима к **атаке расширения длины** (length extension attack): если известен `SHA256(secret || message)`, атакующий может вычислить `SHA256(secret || message || padding || extension)` без знания `secret`.

```
Атака: знаем H(secret || message), хотим создать H(secret || message || ext)
Поскольку H = compress(H_prev, block), мы можем «продолжить» итерацию!
```

Это не позволяет использовать `SHA256(key || message)` как MAC — нужен HMAC.

## 4. SHA-3 (Keccak) — губчатая конструкция

SHA-3 был стандартизирован NIST в 2015 году по итогам конкурса 2007-2012 годов. Победителем стал алгоритм **Keccak**, разработанный Гвидо Бертони (Guido Bertoni), Йоаном Даймен (Joan Daemen), Микаэлем Питерсом (Michaël Peeters) и Жилем Ван Аше (Gilles Van Assche).

### Принципиальное отличие от SHA-2

SHA-3 не использует конструкцию Меркла-Дамгора. Вместо этого используется **губчатая конструкция** (sponge construction), устойчивая к атаке расширения длины.

### Sponge Construction (губчатая конструкция)

Губка имеет внутреннее **состояние** (state) из `b = r + c` бит:
- `r` — **скорость** (rate): биты, взаимодействующие с вводом/выводом
- `c` — **ёмкость** (capacity): биты безопасности

Работа состоит из двух фаз:

**Absorb (поглощение):**
1. Разбиваем входные данные на блоки по `r` бит
2. Для каждого блока: `state[0..r] ^= block`, затем применяем перестановку `f`
3. Перестановка перемешивает все `b = r + c` бит состояния

**Squeeze (выжимание):**
1. Берём первые `r` бит состояния — это `r` бит выхода
2. Если нужно больше, применяем перестановку снова, берём следующие `r` бит
3. Продолжаем до получения нужной длины

```
Сообщение → [pad] → блок₁|блок₂|...|блокₙ
                         ↓      ↓          ↓
Состояние:  |r|c| → ⊕,f → ⊕,f → ... → ⊕,f → squeeze
```

### Параметры SHA-3

| Вариант      | r (rate) | c (capacity) | Выход     |
|-------------|---------|--------------|-----------|
| SHA3-224    | 1152    | 448          | 224 бит   |
| SHA3-256    | 1088    | 512          | 256 бит   |
| SHA3-384    | 832     | 768          | 384 бит   |
| SHA3-512    | 576     | 1024         | 512 бит   |
| SHAKE128    | 1344    | 256          | Переменный|
| SHAKE256    | 1088    | 512          | Переменный|

SHAKE (Secure Hash Algorithm with Keccak) — **расширяемые функции вывода** (XOF, eXtendable Output Function): можно запросить хеш произвольной длины.

### Permutation Keccak-f[1600]

Перестановка Keccak работает с состоянием 5×5×64 бит (1600 бит). За 24 раунда применяются 5 операций:

- **θ (theta):** XOR-диффузия через все колонки
- **ρ (rho):** циклические сдвиги
- **π (pi):** перемещение между дорожками
- **χ (chi):** нелинейная операция (единственная нелинейность)
- **ι (iota):** добавление раундовой константы

```python
import hashlib

# SHA-3 в стандартной библиотеке Python
data = b"Hello, SHA-3!"

sha3_256 = hashlib.sha3_256(data).hexdigest()
sha3_512 = hashlib.sha3_512(data).hexdigest()
print(f"SHA3-256: {sha3_256}")
print(f"SHA3-512: {sha3_512[:64]}...")

# SHAKE256 с переменным выводом
shake = hashlib.shake_256(data)
print(f"SHAKE256-128bit: {shake.hexdigest(16)}")  # 16 байт = 128 бит
print(f"SHAKE256-512bit: {shake.hexdigest(64)}")  # 64 байта = 512 бит

# Проверка отсутствия length extension attack
import hmac
# SHA-3 не уязвима, но всё равно рекомендуется использовать HMAC для MAC
```

## 5. BLAKE3 — быстрый, параллельный, современный

BLAKE3 выпущен в 2020 году командой во главе с Джек О'Коннор (Jack O'Connor). Основан на BLAKE2 (победитель конкурса SHA-3, занял второе место), который в свою очередь происходит от ChaCha/Salsa20.

### Ключевые особенности BLAKE3

1. **Скорость:** значительно быстрее SHA-256, SHA-3, BLAKE2 на современных CPU
2. **Параллелизм:** использует дерево Меркла для параллельной обработки
3. **Одна функция — множество применений:** хеш, MAC (keyed), KDF, PRF (XOF)
4. **SIMD оптимизация:** активно использует AVX-512, AVX2, SSE4.1

### Архитектура BLAKE3

BLAKE3 строит **дерево Меркла** из блоков входных данных (по 1024 байта). Каждый лист дерева — сжатый хеш блока (8 раундов ChaCha-подобной функции). Листья можно обрабатывать параллельно, что обеспечивает ускорение на многоядерных CPU.

```
Входные данные:
[блок₁][блок₂][блок₃][блок₄][блок₅][блок₆][блок₇][блок₈]
   ↓      ↓      ↓      ↓      ↓      ↓      ↓      ↓
  h₁    h₂    h₃    h₄    h₅    h₆    h₇    h₈   ← параллельно
   \    /      \    /      \    /      \    /
  h₁₂          h₃₄          h₅₆          h₇₈     ← параллельно
      \              /            \              /
      h₁₂₃₄                    h₅₆₇₈
              \                  /
              BLAKE3 root hash                    ← финальный хеш
```

### Скорость BLAKE3 vs SHA-2 vs SHA-3

Типичные числа для современного x86-64 CPU (ориентировочно):

| Алгоритм    | Скорость (один поток) | Параллельно |
|-------------|----------------------|-------------|
| MD5         | ~800 МБ/с            | —           |
| SHA-1       | ~500 МБ/с            | —           |
| SHA-256     | ~250 МБ/с (с SHA-NI) | Нет         |
| SHA3-256    | ~300 МБ/с            | Нет         |
| BLAKE2b     | ~700 МБ/с            | Нет         |
| BLAKE3      | ~2 ГБ/с              | Линейно от ядер |

```python
# Установка: pip install blake3
import blake3
import hashlib
import time

data = b"x" * (10 * 1024 * 1024)  # 10 МБ

# BLAKE3
start = time.perf_counter()
h_blake3 = blake3.blake3(data).hexdigest()
t_blake3 = time.perf_counter() - start
print(f"BLAKE3:   {h_blake3[:16]}... ({len(data)/t_blake3/1e6:.0f} МБ/с)")

# SHA-256 для сравнения
start = time.perf_counter()
h_sha256 = hashlib.sha256(data).hexdigest()
t_sha256 = time.perf_counter() - start
print(f"SHA-256:  {h_sha256[:16]}... ({len(data)/t_sha256/1e6:.0f} МБ/с)")

# BLAKE3 как MAC (keyed hash)
key = b'\x42' * 32  # 256-битный ключ
mac = blake3.blake3(data, key=key).hexdigest()
print(f"BLAKE3-MAC: {mac[:32]}...")

# BLAKE3 как KDF (derive_key)
context = "MyApp 2024 session key"
derived = blake3.blake3(data, derive_key_context=context).digest()
print(f"BLAKE3-KDF: {derived.hex()[:32]}...")
```

## 6. Применение хеш-функций

### Проверка целостности файлов

```python
import hashlib
from pathlib import Path

def verify_file_integrity(filepath: str, expected_hash: str, algorithm: str = "sha256") -> bool:
    """Проверка целостности файла по хешу"""
    h = hashlib.new(algorithm)
    with open(filepath, 'rb') as f:
        while chunk := f.read(65536):
            h.update(chunk)
    
    computed = h.hexdigest()
    
    # Timing-safe сравнение (защита от timing attack)
    return hmac.compare_digest(computed.lower(), expected_hash.lower())

import hmac

# Создание контрольной суммы дистрибутива
path = "/etc/hosts"
sha256sum = hashlib.sha256(Path(path).read_bytes()).hexdigest()
print(f"SHA256: {sha256sum}  {path}")

# Аналог команды sha256sum:
# sha256sum /etc/hosts
```

### Хеш в цифровых подписях

В схемах цифровой подписи подписывается не сам документ, а его хеш:

```python
from cryptography.hazmat.primitives.asymmetric import rsa, padding
from cryptography.hazmat.primitives import hashes, serialization

# Генерация ключей
private_key = rsa.generate_private_key(public_exponent=65537, key_size=2048)
public_key = private_key.public_key()

document = b"Я согласен с условиями договора. Подписант: Иванов И.И."

# Подписание: hash(document) подписывается закрытым ключом
signature = private_key.sign(
    document,
    padding.PSS(
        mgf=padding.MGF1(hashes.SHA256()),
        salt_length=padding.PSS.MAX_LENGTH
    ),
    hashes.SHA256()  # Хеш документа
)
print(f"Подпись: {len(signature)} байт")

# Верификация: hash(document) проверяется открытым ключом
try:
    public_key.verify(
        signature,
        document,
        padding.PSS(
            mgf=padding.MGF1(hashes.SHA256()),
            salt_length=padding.PSS.MAX_LENGTH
        ),
        hashes.SHA256()
    )
    print("Подпись верна!")
except Exception:
    print("Подпись недействительна!")
```

### Хеширование паролей — почему НЕ SHA

Криптографические хеш-функции (SHA-256, SHA-3, BLAKE3) **не подходят для хранения паролей**:

1. **Слишком быстрые:** миллиарды вычислений в секунду на GPU → брутфорс тривиален
2. **Нет соли по умолчанию:** одинаковые пароли → одинаковые хеши → rainbow tables
3. **Статичный work factor:** нельзя увеличить сложность без перехеширования

Для паролей используются специальные **slow hash** функции: bcrypt, scrypt, Argon2. Подробнее — в статье о KDF.

```python
# НЕПРАВИЛЬНО для паролей:
bad_hash = hashlib.sha256(b"mypassword").hexdigest()

# ПРАВИЛЬНО для паролей (используйте Argon2):
import argon2
ph = argon2.PasswordHasher()
good_hash = ph.hash("mypassword")
```

## Заключение

Криптографические хеш-функции — незаменимый инструмент в арсенале разработчика. Ключевые выводы:

1. **SHA-1 и MD5 — устарели** и не должны использоваться для безопасности. Git всё ещё использует SHA-1 для объектов, но переходит на SHA-256.

2. **SHA-256** — надёжный выбор для большинства случаев: проверка целостности файлов, цифровые подписи, HMAC, блокчейн.

3. **SHA-3/Keccak** — альтернатива с принципиально другой конструкцией, устойчивой к length extension attack. Предпочтителен там, где важна диверсификация алгоритмов.

4. **BLAKE3** — современный выбор для высокоскоростных применений (верификация больших файлов, деревья Меркла). Параллельная архитектура особенно эффективна на многоядерных системах.

5. **Для паролей** — используйте Argon2, bcrypt или scrypt, а не обычные хеш-функции.
