# Hamming, Reed-Solomon: коды, исправляющие ошибки

Контрольные суммы обнаруживают ошибки, но ничего не могут с ними сделать — только сообщить о проблеме. Коды, исправляющие ошибки (Error-Correcting Codes, ECC), делают шаг вперёд: они не только обнаруживают, но и **исправляют** ошибки автоматически. Именно благодаря этой технологии Voyager передаёт фотографии с расстояния в миллиарды километров, QR-код читается даже при повреждении, а CD воспроизводится несмотря на царапины.

## Обнаружение vs Исправление

Прежде чем рассматривать алгоритмы, разберём разницу.

**Error detection (обнаружение):** Мы знаем, что произошла ошибка, но не знаем где. Например, CRC-32.

**Error correction (исправление):** Мы знаем, что произошла ошибка, и можем её восстановить без повторного запроса данных.

**Erasure correction:** Мы знаем, какие позиции стёрты (erased), но не знаем их значений. Это проще, чем исправление случайных ошибок.

### Расстояние Хэмминга

Расстояние Хэмминга между двумя словами одинаковой длины — количество позиций, в которых они отличаются.

```python
def hamming_distance(a: str, b: str) -> int:
    """Расстояние Хэмминга между двумя строками"""
    assert len(a) == len(b), "Строки должны быть одинаковой длины"
    return sum(c1 != c2 for c1, c2 in zip(a, b))

# Примеры:
print(hamming_distance("01010101", "01101001"))  # 3
print(hamming_distance("karolin", "kathrin"))    # 3
print(hamming_distance("1011101", "1001001"))    # 2

# В битах:
a = 0b01010101
b = 0b01101001
print(bin(a ^ b).count('1'))   # 3 — через XOR!
```

### Кодовое расстояние и способность к исправлению

Для кода с минимальным расстоянием d:
- **Обнаружение**: до d-1 ошибок
- **Исправление**: до ⌊(d-1)/2⌋ ошибок

```
d=1: бесполезно (любая ошибка = валидное кодовое слово)
d=2: обнаружение 1 ошибки (нет исправления)
d=3: исправление 1 ошибки (или обнаружение 2)
d=4: исправление 1 ошибки + обнаружение 2 (или только обнаружение 3)
d=5: исправление 2 ошибок
```

## Код Хэмминга (7,4): простейший исправляющий код

Ричард Хэмминг (Bell Labs, 1950) разработал первый практичный исправляющий код. Код (7,4) кодирует 4 бита данных в 7 битов: добавляется 3 проверочных бита.

### Конструкция кода Хэмминга (7,4)

Позиции 1, 2, 4 (степени двойки) — проверочные биты. Позиции 3, 5, 6, 7 — биты данных.

```
Позиция:  1  2  3  4  5  6  7
Тип:      P  P  D  P  D  D  D

Проверочные биты охватывают:
P1 (pos 1): позиции 1, 3, 5, 7  (биты с 1 в позиции 0)
P2 (pos 2): позиции 2, 3, 6, 7  (биты с 1 в позиции 1)
P4 (pos 4): позиции 4, 5, 6, 7  (биты с 1 в позиции 2)
```

```python
def hamming_encode(data_bits: list) -> list:
    """Кодируем 4 бита в 7-битное кодовое слово Хэмминга"""
    assert len(data_bits) == 4
    
    # Размещаем биты данных на позициях 3,5,6,7
    # (позиции 1-based!)
    d = [0] * 8  # индекс 0 не используется
    d[3], d[5], d[6], d[7] = data_bits
    
    # Вычисляем проверочные биты (XOR позиций в покрытии)
    d[1] = d[3] ^ d[5] ^ d[7]  # P1
    d[2] = d[3] ^ d[6] ^ d[7]  # P2
    d[4] = d[5] ^ d[6] ^ d[7]  # P4
    
    return d[1:]  # возвращаем биты 1-7

def hamming_decode(received: list):
    """Декодируем и исправляем 7-битное кодовое слово"""
    assert len(received) == 7
    
    r = [0] + received  # 1-based indexing
    
    # Syndrome — вычисляем "диагностические биты"
    s1 = r[1] ^ r[3] ^ r[5] ^ r[7]  # должно быть 0
    s2 = r[2] ^ r[3] ^ r[6] ^ r[7]  # должно быть 0
    s4 = r[4] ^ r[5] ^ r[6] ^ r[7]  # должно быть 0
    
    # Syndrome = бинарный номер ошибочной позиции!
    syndrome = s4 * 4 + s2 * 2 + s1
    
    if syndrome > 0:
        print(f"Ошибка на позиции {syndrome}! Исправляем...")
        r[syndrome] ^= 1  # инвертируем ошибочный бит
    
    # Извлекаем биты данных с позиций 3,5,6,7
    return [r[3], r[5], r[6], r[7]]

# Пример:
data = [1, 0, 1, 1]
encoded = hamming_encode(data)
print(f"Данные:     {data}")
print(f"Закодировано: {encoded}")
# [1, 0, 1, 0, 0, 1, 1]

# Симулируем ошибку в 5-й позиции:
corrupted = encoded.copy()
corrupted[4] ^= 1  # инвертируем бит 5
print(f"С ошибкой:  {corrupted}")

decoded = hamming_decode(corrupted)
print(f"Декодировано: {decoded}")
# Ошибка на позиции 5! Исправляем...
# [1, 0, 1, 1] — восстановлено!
assert decoded == data
```

### Почему syndrome = позиция ошибки

Каждый проверочный бит Pᵢ покрывает позиции, у которых установлен i-й бит в двоичной записи позиции:

```
Позиция:  1    2    3    4    5    6    7
Двоичная: 001  010  011  100  101  110  111

P1 (001) проверяет: 1,3,5,7 (все с 1 в позиции 0)
P2 (010) проверяет: 2,3,6,7 (все с 1 в позиции 1)
P4 (100) проверяет: 4,5,6,7 (все с 1 в позиции 2)

Если ошибка на позиции 5 (101):
- P1 обнаружит (5 в покрытии P1): s1=1
- P2 НЕ обнаружит (5 не в покрытии P2): s2=0
- P4 обнаружит (5 в покрытии P4): s4=1

syndrome = 4*1 + 2*0 + 1*1 = 5 ← именно позиция ошибки!
```

Это элегантное математическое свойство: синдром — это двоичный номер позиции ошибки.

### SECDED: Single Error Correct, Double Error Detect

В реальных системах памяти ECC используется расширение кода Хэмминга — **SECDED** (добавляется ещё один проверочный бит для общего чётности):

```
Код (8,4): исправляет 1 ошибку, обнаруживает 2
Код (72,64): стандарт ECC памяти — 64 бита данных + 8 бит ECC

DIMM с ECC:
- Обычная DIMM: 64-битная шина
- ECC DIMM: 72-битная шина (64 + 8 ECC)
- Молча исправляет однобитные ошибки
- Сигнализирует о двухбитных ошибках
```

## Reed-Solomon: мощные коды на полях Галуа

Код Хэмминга исправляет только одну ошибку. Для реальных применений (CD/DVD, QR-код, космос) нужны более мощные коды. Тут приходит **Reed-Solomon** (1960).

### Математическая идея

Reed-Solomon работает не с отдельными битами, а с **символами** (байтами или группами битов). Ключевая идея: **полином степени k-1 полностью определяется k точками**.

```
Если данные — это коэффициенты полинома p(x) степени k-1,
то n значений p(α⁰), p(α¹), ..., p(αⁿ⁻¹) — это кодовое слово.

Мы вычисляем n > k значений полинома.
Любые k из n значений могут восстановить полином!
Остальные n-k значений — избыточность.
```

Это работает над **полем Галуа GF(2^m)**, где арифметика замкнута и обратимы все ненулевые элементы.

### Reed-Solomon (n, k) в числах

Код RS(n, k) кодирует k символов данных в n символов:
- **n-k** — количество проверочных символов (redundancy)
- Обнаруживает до **n-k** ошибок (стираний)
- Исправляет до **(n-k)/2** ошибок

```
RS(255, 223) для космических зондов:
- 223 байта данных
- 32 байта проверочных символов
- Исправляет до 16 байт ошибок

RS(255, 235) в стандарте QR-кода уровень M:
- Исправляет ~15% ошибочных символов

CD Audio: RS(28, 24) + RS(32, 28) двойной код
- 24 байта данных
- 8 байт проверочных в первом уровне
- Итого 32+8 = 40 байт, второй уровень
```

### Пример RS в QR-коде

```
QR-код уровень L (Low):
- Восстанавливает до 7% данных

QR-код уровень H (High):
- Восстанавливает до 30% данных
- Можно закрыть логотипом до 30% кода!
```

```python
# pip install reedsolo
import reedsolo

# Кодируем с помощью Reed-Solomon
rsc = reedsolo.RSCodec(10)  # 10 байт ECC

data = b"Hello, World!"
encoded = rsc.encode(data)
print(f"Оригинал:  {data.hex()}")
print(f"Закодовано: {encoded.hex()}")
print(f"Длина: {len(data)} → {len(encoded)} байт (+{len(encoded)-len(data)} ECC)")

# Симулируем ошибки (до 5 байт — исправим!)
corrupted = bytearray(encoded)
corrupted[0] = 0xFF   # ошибка в байте 0
corrupted[5] = 0xAA   # ошибка в байте 5
corrupted[10] = 0x00  # ошибка в байте 10

decoded, decoded_msgecc, errata_pos = rsc.decode(bytes(corrupted))
print(f"Восстановлено: {decoded}")
print(f"Позиции ошибок: {errata_pos}")
# b"Hello, World!" — исправлено!
```

### Reed-Solomon в CD/DVD

CD Audio использует сложную двойную схему кодирования CIRC (Cross-Interleaved Reed-Solomon Coding):

```
Данные → RS C2 кодирование → перемежение (interleaving) → RS C1 кодирование

C2: RS(28, 24) — исправляет до 2 символов
C1: RS(32, 28) — исправляет до 2 символов

Перемежение (interleaving): разбрасывает соседние байты
по разным секторам диска!

Зачем перемежение?
- Царапина на CD уничтожает соседние байты
- Без перемежения: длинная последовательность ошибок → C1 не справится
- С перемежением: соседние байты оказываются на разных позициях
  → каждый блок содержит не более 1-2 ошибок → легко исправить

Результат: CD Audio восстанавливает ошибки при царапинах
длиной до ~2.5 мм!
```

### Reed-Solomon для глубокого космоса

Космические зонды Voyager (1977) используют конкатенированное кодирование:

```

```

## RAID-6 и двойная чётность

RAID-6 (Redundant Array of Independent Disks, уровень 6) использует коды Reed-Solomon для защиты от отказа **двух** дисков одновременно.

### RAID-5 vs RAID-6

```
RAID-5: N дисков данных + 1 диск чётности
- Выдерживает отказ 1 диска
- Восстановление: XOR всех оставшихся дисков

RAID-6: N дисков данных + 2 диска чётности (P и Q)
- Выдерживает отказ 2 дисков одновременно
- Требует два независимых уравнения
```

### Математика RAID-6

RAID-6 использует **два** вида чётности:

```
P = D₁ XOR D₂ XOR D₃ XOR ... (обычная XOR чётность, как RAID-5)

Q = g⁰·D₁ XOR g¹·D₂ XOR g²·D₃ XOR ...
    (где g — генератор поля GF(2^8), умножение в GF(2^8)!)
```

Имея P и Q, можно восстановить любые два отказавших диска, решив систему двух уравнений.

```python
def gf_mult(a, b, poly=0x11D):
    """Умножение в GF(2^8) с полиномом 0x11D"""
    result = 0
    while b:
        if b & 1:
            result ^= a
        a = (a << 1) ^ poly if a & 0x80 else a << 1
        b >>= 1
    return result & 0xFF

def compute_raid6_parity(blocks):
    """Вычисляем P и Q чётности для RAID-6"""
    n = len(blocks)
    length = len(blocks[0])
    
    P = bytes(length)
    Q = bytes(length)
    
    for i, block in enumerate(blocks):
        # P = XOR всех блоков
        P = bytes(a ^ b for a, b in zip(P, block))
        
        # Q = g^i * block для каждого блока, все XOR
        g_i = 1  # g^0 = 1
        for j in range(i):
            g_i = gf_mult(g_i, 2)  # умножаем на g=2 в GF(2^8)
        
        Q_term = bytes(gf_mult(g_i, byte) for byte in block)
        Q = bytes(a ^ b for a, b in zip(Q, Q_term))
    
    return P, Q
```

## Турбо-коды и LDPC для 5G

Современные системы связи (LTE, 5G, спутниковая связь, WiFi) используют гораздо более мощные коды.

### Турбо-коды (1993)

Турбо-коды — революция в теории кодирования. Они почти достигают предела Шеннона при практической сложности декодирования.

Идея: два рекурсивных систематических сверточных кодера соединены **интерливером** (перемешивающим устройством). Декодирование итеративное — кодеры "передают информацию" друг другу, уточняя результат.

```
Используются в: 3G (WCDMA), 4G LTE (downlink)
Производительность: ~0.5 dB от предела Шеннона
```

### LDPC (Low-Density Parity-Check Codes)

LDPC коды (Галлагер, 1963; переоткрыты в 1996) — спарсивные коды проверки чётности.

```
Используются в: 5G NR, WiFi 802.11n/ac/ax, CCSDS (космические зонды)
Производительность: ~0.04 dB от предела Шеннона (почти идеально!)
```

```
5G NR использует два типа кодов:
- LDPC для данных (высокая пропускная способность)
- Polar codes для управляющих каналов (хорошо для коротких блоков)
```

## Практические примеры исправления ошибок

### ECC памяти: защита от "single bit flips"

```
Современные серверы используют ECC RAM:
- DDR4 ECC: 64 бита данных + 8 бит ECC (на каждые 8 байт)
- Исправляет: 1 битовую ошибку (SECDED)
- Обнаруживает: 2 битовые ошибки

Откуда берутся ошибки в RAM?
- Cosmic rays (космические лучи) — ~1 ошибка на 4GB в месяц!
- Alpha particles от корпуса микросхемы
- Capacitor leakage

Для систем с 256 GB RAM: несколько ошибок в сутки без ECC!
```

### Проверка наличия ECC в Linux

```bash
# Проверить, использует ли система ECC RAM
dmidecode --type 17 | grep "Error Correction Type"
# Error Correction Type: Multi-bit ECC

# Мониторинг ошибок ECC:
edac-util -s  # нужен edac-utils
# или
cat /sys/devices/system/edac/mc/mc0/ue_count  # uncorrectable errors
cat /sys/devices/system/edac/mc/mc0/ce_count  # correctable errors
```

### Коррекция ошибок при записи Flash памяти (SSD, NAND)

```
NAND Flash ненадёжна:
- Каждая ячейка может хранить данные ограниченное число записей
- MLC/TLC NAND: до 3000-10000 циклов записи
- После этого — bit errors

SSD контроллер использует LDPC:
- Современные SSD: BCH или LDPC коды
- Samsung 870 EVO: LDPC с исправлением до 72 ошибок на КБ!
- Прозрачно для пользователя
```

## Итоги

Коды исправления ошибок — мост между ненадёжным физическим миром и надёжными цифровыми данными:

1. **Расстояние Хэмминга** — фундаментальная метрика для теории кодов
2. **Код Хэмминга (7,4)** — простейший исправляющий код; основа ECC RAM
3. **SECDED** — стандарт для серверной памяти
4. **Reed-Solomon** — мощный код на полях Галуа для CD/DVD, QR, космоса, RAID-6
5. **LDPC и Polar коды** — современные стандарты 5G, WiFi

Без ECC не работали бы ни CD-плееры, ни космические зонды, ни быстрые SSD, ни надёжные серверы.
