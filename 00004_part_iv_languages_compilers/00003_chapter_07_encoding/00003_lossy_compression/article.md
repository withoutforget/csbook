# Кодирование с потерями: JPEG, MP3, H.264 — компромисс качество/размер

Фотография с телефона может занимать 3-5 МБ в JPEG вместо 20+ МБ несжатого RAW. Музыкальный файл MP3 в 3-5 МБ содержит то же самое, что CD-трек в 50 МБ. Видео в 4K разрешении умещается на диск вместо того, чтобы требовать терабайты. Всё это — кодирование с потерями (lossy compression), основанное на одной глубокой идее: человеческое восприятие несовершенно, и потери которые мы не замечаем — это не потери.

## Психофизические основы: что мы не замечаем

### Зрительная система

Зрение человека — не камера. Это активная система с множеством особенностей, которые можно эксплуатировать при сжатии:

1. **Чувствительность к яркости выше, чем к цвету.** Наш глаз содержит ~120 миллионов палочек (чувствительных к яркости) и ~6 миллионов колбочек (чувствительных к цвету). Поэтому можно хранить цвет с меньшим разрешением.

2. **Высокочастотные детали воспринимаются хуже.** Нам труднее различить мелкие изменения на высокочастотных деталях (мелкая текстура), чем на крупных объектах.

3. **Маскировка:** Яркие области маскируют дефекты в соседних тёмных.

4. **Чувствительность нелинейна:** Мы лучше замечаем изменения в тёмных областях, чем в ярких (Weber's law).

### Слуховая система

MP3 эксплуатирует ограничения слуха:

1. **Порог слышимости зависит от частоты.** Человек слышит 20 Гц – 20 кГц, но хуже — на краях диапазона.

2. **Одновременная маскировка:** Громкий звук маскирует тихий на близкой частоте.

3. **Временная маскировка:** Громкий звук маскирует тихий за несколько миллисекунд до и после.

4. **Эффект критических полос:** Ухо группирует близкие частоты.

## JPEG: изображения с потерями

JPEG (Joint Photographic Experts Group, 1992) — стандарт сжатия фотографий. Полный pipeline состоит из нескольких шагов.

### Шаг 1: Преобразование цветового пространства (RGB → YCbCr)

```
Y  = 0.299·R + 0.587·G + 0.114·B  — яркость (luma)
Cb = -0.169·R - 0.331·G + 0.500·B — синяя хроматика
Cr =  0.500·R - 0.419·G - 0.081·B — красная хроматика
```

Человек лучше различает яркость (Y), чем цветовые компоненты (Cb, Cr). Это критически важно для следующего шага.

```python
import numpy as np

def rgb_to_ycbcr(image_rgb):
    """Преобразование RGB в YCbCr"""
    # image_rgb: массив shape (H, W, 3), значения 0-255
    R, G, B = image_rgb[:,:,0], image_rgb[:,:,1], image_rgb[:,:,2]
    
    Y  =  0.299  * R + 0.587  * G + 0.114  * B
    Cb = -0.169  * R - 0.331  * G + 0.500  * B + 128
    Cr =  0.500  * R - 0.419  * G - 0.081  * B + 128
    
    return np.stack([Y, Cb, Cr], axis=2).astype(np.uint8)
```

### Шаг 2: Субдискретизация хроматики (Chroma Subsampling)

Раз глаз нечувствителен к цветовым деталям, уменьшим разрешение Cb и Cr:

```
Форматы субдискретизации (J:a:b нотация):
4:4:4 — без субдискретизации, полное качество
4:2:2 — Cb и Cr уменьшены вдвое по горизонтали  
4:2:0 — Cb и Cb уменьшены вдвое по обоим направлениям (JPEG default)

При 4:2:0:
- Y канал: 1920×1080 пикселей
- Cb канал: 960×540 пикселей
- Cr канал: 960×540 пикселей
Итого: (1920*1080 + 960*540 + 960*540) = 2 073 600 + 518 400 + 518 400 = 3 110 400
vs 6 220 800 пикселей в 4:4:4 — уже вдвое меньше данных!
```

### Шаг 3: Разбиение на блоки 8×8

Каждый канал разбивается на блоки 8×8 пикселей. Это единица обработки в JPEG.

```
┌─────────────┐
│ 8×8 блок   │
│ 64 значения │
│ яркости     │
└─────────────┘
```

Вычитаем 128 из каждого значения (центрируем от [0,255] до [-128,127]):

```python
def prepare_block(block_8x8):
    """Центрируем блок 8x8 для DCT"""
    return block_8x8.astype(float) - 128
```

### Шаг 4: DCT (Discrete Cosine Transform)

Дискретное косинусное преобразование переводит пространственные данные в частотные. Это ключевой шаг JPEG.

Для блока 8×8 двумерный DCT-II:

```
F(u,v) = (1/4) · C(u) · C(v) · Σᵢ Σⱼ f(i,j) · cos((2i+1)uπ/16) · cos((2j+1)vπ/16)

где C(0) = 1/√2, C(k) = 1 для k > 0
```

Результат — матрица 8×8 частотных коэффициентов:
- `F(0,0)` — DC компонент (средняя яркость блока)
- Остальные — AC компоненты (детали разной пространственной частоты)

```python
from scipy.fft import dctn, idctn

def apply_dct(block):
    """2D DCT для блока 8x8"""
    return dctn(block, norm='ortho')

def apply_idct(dct_block):
    """Обратный 2D DCT"""
    return idctn(dct_block, norm='ortho')

# Пример:
block = np.array([
    [52, 55, 61, 66, 70, 61, 64, 73],
    [63, 59, 55, 90, 109, 85, 69, 72],
    # ... ещё 6 строк
], dtype=float)

block_centered = block - 128
dct_coeffs = apply_dct(block_centered)

# После DCT большинство значений близки к 0 — это основа сжатия!
# Высокочастотные коэффициенты (правый нижний угол) малы и важны меньше
```

### Шаг 5: Квантование

Это единственный **необратимый** шаг JPEG. Каждый DCT-коэффициент делится на соответствующее значение из **таблицы квантования** и округляется до целого:

```python
# Стандартная таблица квантования яркости (качество 50)
QUANT_LUMA_50 = np.array([
    [16, 11, 10, 16, 24,  40,  51,  61],
    [12, 12, 14, 19, 26,  58,  60,  55],
    [14, 13, 16, 24, 40,  57,  69,  56],
    [14, 17, 22, 29, 51,  87,  80,  62],
    [18, 22, 37, 56, 68,  109, 103, 77],
    [24, 35, 55, 64, 81,  104, 113, 92],
    [49, 64, 78, 87, 103, 121, 120, 101],
    [72, 92, 95, 98, 112, 100, 103, 99 ]
])

def quantize(dct_block, quant_table):
    """Квантование: потери информации здесь!"""
    return np.round(dct_block / quant_table).astype(int)

def dequantize(quant_block, quant_table):
    """Деквантование: восстанавливаем приближённо"""
    return quant_block * quant_table
```

Высокочастотные коэффициенты (правый нижний угол) делятся на большие числа → округляются до 0. Это "потери" в lossy compression.

**Управление качеством:** При выборе "качество 80%" в JPEG редакторе таблица квантования масштабируется: меньшие значения → меньше потерь → больший файл.

### Шаг 6: Zigzag сканирование

После квантования большинство высокочастотных коэффициентов равны 0. Zigzag сканирование упорядочивает 64 коэффициента так, что нули группируются в конце:

```
Zigzag порядок обхода 8×8 матрицы:
 0  1  5  6 14 15 27 28
 2  4  7 13 16 26 29 42
 3  8 12 17 25 30 41 43
 9 11 18 24 31 40 44 53
10 19 23 32 39 45 52 54
20 22 33 38 46 51 55 60
21 34 37 47 50 56 59 61
35 36 48 49 57 58 62 63

→ [DC, AC1, AC2, AC3, ..., 0, 0, 0, 0, 0, 0, ...]
                                ^-- высокочастотные нули в конце
```

### Шаг 7: RLE и кодирование Хаффмана

Последовательность нулей в конце кодируется через **Run-Length Encoding (RLE)**: хранится (количество нулей, ненулевое значение).

Специальный код `EOB` (End of Block) указывает что остальные коэффициенты равны нулю.

Наконец, Хаффман-кодирование применяется ко всему потоку.

### PNG vs JPEG

```
JPEG:
- Lossy (потери при каждом сохранении!)
- Хорош для фотографий
- Плохой выбор для текста, логотипов, скриншотов
- Артефакты: "JPEG блокировость" при высоком сжатии

PNG:
- Lossless (без потерь!)
- Хорош для графики с чёткими краями
- Файлы больше для фотографий
- Поддержка прозрачности (альфа-канал)
- Алгоритм: PNG filter + zlib DEFLATE
```

## MP3: психоакустическое сжатие аудио

MP3 (MPEG-1 Audio Layer III, 1991-1995) — стандарт, изменивший музыкальную индустрию. Сжимает аудио в 10 раз с минимально заметными потерями.

### Шаг 1: Субполосный анализ (Subband Analysis)

Аудиосигнал делится на 32 субполосы через полифазный фильтровый банк. Каждая субполоса содержит определённый частотный диапазон.

```
Частотный диапазон 0-22050 Гц делится на 32 равные полосы:
Полоса 0: 0-689 Гц
Полоса 1: 689-1378 Гц
...
Полоса 31: 21361-22050 Гц
```

### Шаг 2: Психоакустическая модель

Параллельно вычисляется психоакустическая модель — определяет, что в каждый момент времени можно не слышать:

1. **Абсолютный порог слышимости:** минимальный уровень звука в тишине для каждой частоты

2. **Маскировочный порог:** сколько шума допустимо в каждой полосе с учётом эффектов маскировки

```python
# Концептуальная иллюстрация маскировки
def get_masking_threshold(spectrum, freq_bands):
    """Упрощённая модель маскировки"""
    threshold = absolute_hearing_threshold(freq_bands)
    
    for i, level in enumerate(spectrum):
        if level > threshold[i]:
            # Этот сигнал маскирует соседние
            for j in range(len(freq_bands)):
                # Маскировочный эффект уменьшается с расстоянием
                spread = spreading_function(i, j)
                threshold[j] = max(threshold[j], level - spread)
    
    return threshold
```

### Шаг 3: MDCT (Modified Discrete Cosine Transform)

В отличие от JPEG, MP3 использует MDCT — модифицированное DCT с перекрывающимися окнами. Размер окна переключается между 36 (для стационарных сигналов) и 12 выборок (для атак — резких звуков).

### Шаг 4: Квантование и распределение бит

Коэффициенты MDCT квантуются с разным количеством бит для каждой полосы. Полосы с высоким маскировочным порогом — больше шума допустимо — получают меньше бит.

```
Принцип: бюджет бит распределяется пропорционально "слышимости"
- Тихие полосы: мало бит (всё равно не слышно)
- Маскированные полосы: мало бит
- Слышимые полосы: много бит (важны для качества)
```

### Шаг 5: Хаффман-кодирование

Наконец, квантованные коэффициенты кодируются Хаффманом. MP3 использует 32 предопределённые таблицы Хаффмана.

### Битрейты и качество MP3

```
Битрейт | Размер (4 мин) | Качество
32 kbps | ~1 МБ         | AM-радио, плохое
128 kbps| ~3.8 МБ       | "CD-качество" для большинства
192 kbps| ~5.7 МБ       | Хорошее качество
320 kbps| ~9.6 МБ       | Максимальное качество MP3
(CD)    | ~50 МБ        | Lossless 16bit/44.1kHz
```

### Современные форматы: AAC, Opus

**AAC (Advanced Audio Coding):** Официальный преемник MP3 (1997). Лучшее качество при том же битрейте. Используется в iTunes, YouTube, iPhone.

**Opus:** Современный открытый кодек (2012). Превосходит MP3 и AAC. Оптимизирован для воспроизведения речи (SILK) и музыки (CELT). Используется в WebRTC, Discord, Zoom.

## H.264/AVC: видеосжатие нового поколения

H.264 (Advanced Video Coding, 2003) — стандарт видеосжатия, ставший основой streaming'а, Blu-ray, видеоконференций. Достигает сжатия в 100-1000 раз по сравнению с несжатым видео.

### Ключевые концепции

**Frame types (типы кадров):**

```
I-кадр (Intra):    Самодостаточный, как JPEG. Каждые ~30 кадров (GOP)
P-кадр (Predicted): Предсказан из предыдущего кадра
B-кадр (Bidirectional): Предсказан из предыдущего И следующего

Типичная GOP (Group of Pictures):
I P B B P B B P B B P B B I...
^                           ^-- следующий I-кадр
I-кадр: ~100% данных
P-кадр: ~20-30% от I
B-кадр: ~10-20% от I
```

### Intra-frame prediction

Внутри одного кадра блоки предсказываются из уже декодированных соседних:

```
┌────┬────┐
│ A  │ B  │  
├────┼────┤
│ C  │ ?  │  ← предсказываем из A, B, C
└────┴────┘

Режимы предсказания:
- Vertical: копируем из блока выше (B)
- Horizontal: копируем из блока слева (C)
- DC: среднее A, B, C
- Diagonal и другие (всего 9 режимов для 4x4, 4 для 16x16)

Кодируется разница между предсказанием и реальностью (residual)!
```

### Inter-frame prediction и Motion Compensation

Самая мощная техника H.264: **motion compensation** (компенсация движения).

```
Кадр t-1:           Кадр t:
┌───────────┐       ┌───────────┐
│ [авто]    │       │  [авто]   │
│     →     │  →   │    →      │  
│           │       │           │
└───────────┘       └───────────┘

Вместо хранения кадра t:
1. Найти блок в кадре t-1, похожий на блок в кадре t
2. Хранить вектор движения (Motion Vector): (dx, dy)
3. Хранить разницу (residual): кадр_t - предсказание

Если блок почти не изменился → residual ≈ 0 → хранить почти нечего!
```

### Макроблоки и иерархическое кодирование

H.264 разбивает кадр на макроблоки 16×16. Внутри каждого макроблока возможно разбиение на блоки меньших размеров (16×8, 8×16, 8×8, 4×4) для лучшего соответствия содержимому.

### Энтропийное кодирование: CABAC

H.264 использует **CABAC (Context-Adaptive Binary Arithmetic Coding)** — адаптивное арифметическое кодирование, значительно превосходящее Хаффман для видео.

### H.265/HEVC и H.266/VVC

**H.265/HEVC (2013):** В 2 раза лучше H.264 при том же качестве. Используется для 4K.
**H.266/VVC (2020):** В 2 раза лучше H.265. Для 8K и выше.

Эволюция:
```
H.264:  1x   (базовый)
H.265:  2x   (в 2 раза лучше H.264)
H.266:  4x   (в 4 раза лучше H.264)
AV1:    ~2x  (открытый, Google/Mozilla/Amazon)
```

## WebP и AVIF: современные форматы изображений

### WebP

WebP (Google, 2010) — веб-формат, заменяющий JPEG и PNG:

- **Lossy WebP:** Основан на VP8 (видеокодек). Примерно на 25-35% лучше JPEG.
- **Lossless WebP:** Основан на VP8L. Примерно на 25% лучше PNG.
- **Animated WebP:** Альтернатива GIF с лучшим качеством и меньшим размером.

### AVIF

AVIF (AV1 Image File Format, 2019) — основан на ключевых кадрах видеокодека AV1:

- В 2-3 раза лучше JPEG при том же качестве
- Поддерживает HDR и широкий цветовой охват
- Поддержка в современных браузерах (Chrome 85+, Firefox 86+, Safari 16+)

```html
<!-- Прогрессивный fallback для браузеров -->
<picture>
  <source srcset="photo.avif" type="image/avif">
  <source srcset="photo.webp" type="image/webp">
  <img src="photo.jpg" alt="Photo">
</picture>
```

```python
# Работа с изображениями в Python (Pillow)
from PIL import Image

img = Image.open('photo.jpg')

# Сохранение в WebP
img.save('photo.webp', quality=80)

# Сохранение в AVIF (требует pillow-avif-plugin)
# img.save('photo.avif', quality=80)

# SSIM — метрика структурного сходства (лучше PSNR для изображений)
from skimage.metrics import structural_similarity as ssim
import numpy as np

original = np.array(Image.open('photo.jpg').convert('L'))
compressed = np.array(Image.open('photo.webp').convert('L'))
score = ssim(original, compressed)
print(f"SSIM: {score:.4f}")  # 1.0 = идентично, >0.95 = хорошо
```

## Артефакты сжатия

### JPEG артефакты

```
Блочность (blocking): Видимые квадраты 8×8 при низком качестве
Эффект Гиббса: Ореолы вокруг чётких краёв
Цветовые пятна: Из-за субдискретизации хроматики
```

### MP3 артефакты

```
Pre-echo: Слышно "отражение" атаки перед ней (из-за больших MDCT окон)
Звон: На высоких частотах
Стерео narrowing: При низких битрейтах
```

## Практическое руководство по выбору формата

```
Тип контента → Формат:

Фотографии → WebP (приоритет) > JPEG > AVIF
Логотипы, иконки → SVG > PNG > WebP Lossless
Скриншоты с текстом → PNG > WebP Lossless
Анимации → WebM/MP4 > WebP Anim > GIF (никогда для нового)
Видео → H.264/H.265 (широкая совместимость) > AV1 (лучшее сжатие)
Аудио → Opus > AAC > MP3 (устарел)
Аудио (lossless) → FLAC > Apple Lossless (ALAC)
```

## Итоги

Сжатие с потерями — это союз математики и нейронауки:

1. **JPEG:** DCT + квантование + Хаффман. Использует нечувствительность зрения к высоким частотам и цвету.

2. **MP3:** Субполосный анализ + MDCT + психоакустическая модель + квантование + Хаффман. Эксплуатирует маскировочные эффекты слуха.

3. **H.264:** Motion compensation + intra/inter prediction + DCT на residuals + CABAC. Эксплуатирует временную и пространственную избыточность видео.

Ключевой принцип: **удалить только то, что человек не заметит**. Граница между "заметит" и "не заметит" — психофизическая модель, которая уточняется в каждом поколении кодеков.
